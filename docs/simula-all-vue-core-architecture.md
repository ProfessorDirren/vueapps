# SIMULA: one VUECORE, all VUE specialists

## Non-negotiable architecture
Every VUE is a VUECORE-owned specialist module, never an independent technical island. ANYVUE is a peer specialist in the same family. SIMULA is the recursive, unlimited-depth specialization model: each child inherits shared CORE capabilities and adds **specific, verifiable expertise**. Depth alone must never be represented as greater intelligence.

## Inherited CORE services
- Photo-first workflow, optional video intake when implemented and validated, AI-assisted observations, follow-up questions, uncertainty and recommendations.
- Seven-language support with English default, explicit choice persistence and Arabic RTL.
- Shared model gateway, emergency-first safety rules, privacy boundaries, isolated case memory, specialist selection and handoff.
- Shared HTTPS API contracts, budget controls, tests, deployment and observability.
- Specialist methods, source selection and assessment criteria accumulate along the full SIMULA lineage. No fixed maximum depth.

## Existing foundation and remaining work
The current `core/specialist-tree.js` builds domain and sub-specialist nodes and accepts arbitrarily deep extra nodes. `api/vue-router.js` routes questions and passes a specialist path to the common follow-up API. This is a foundation, not proof that all standalone apps have been migrated.

Audit every VUE against inherited capabilities. Port standalone functions into modules and preserve external entry points during transition. ANIVUE is the first migration candidate, not a special exception. Preserve animal emergency guidance, species logic, photo analysis and veterinary discovery. Do not retire `anivueapp.se` automatically; possible decommission in 2027 requires an explicit later decision.

## Gates before any cutover
1. Inventory every VUE, route, external workspace, feature and data boundary.
2. Define shared interfaces for image/video, specialist requests, emergency handling and results.
3. Add executable contract and SIMULA lineage tests for every specialist, including arbitrarily deep descendants.
4. Implement missing shared services and migrate each specialist behind compatibility routes.
5. Compare Preview with existing production; verify seven languages, privacy, emergency behavior, images, keyboard submission, and rollback.
6. Release progressively, monitor, then consider standalone retirement only after proven parity and approval.
